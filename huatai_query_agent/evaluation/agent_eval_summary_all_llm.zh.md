## 主要发现

1. SQL 可执行性明显强于严格结果等价性。 Agent 为 83.95% 的用例生成了可执行 SQL, 但只有 9.88% 匹配了要求的输出字段和别名。 字段不匹配是最主要的失败类型。
2. 难度分层是有效的。 可执行率从 96.67% 在合成用例集上的水平下降到 60.00% 在高级用例集上的水平; 高级用例精确匹配率为 0%.
3. 较长且口径完整的业务请求有时仍被当作信息不完整处理。 Twelve of the 30 高级 cases 停在 `ask_clarification`, 尽管参考问题已经定义了计算规则。
4. `a027` 直接评测时可成功执行, 但 Agent 围栏报告未知的 CTE 投影别名字段，并将其转入人工复核。 这是校验器误报，而不是 DuckDB 执行失败。
5. 严格精确匹配得分应结合行数匹配和无序行值匹配指标一起解读。 许多候选查询返回了预期行数，但使用了不同别名、遗漏了要求展示的字段，或改变了输出顺序。
